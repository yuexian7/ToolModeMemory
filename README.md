# Tool Mode Memory

记住工具面板设置，并按存档持久化。总开关**默认关闭**；关掉时模组完全不参与 = 原版行为。

> 本地已含 v0.9.2（共用范围「全局共用／全部不共用」两句改成「所有显示这一项的工具……」的口径、
> 去掉了「本页内」这种把页面当设置对象的说法；工具模式与对齐按工具类别拆行，
> 例如「工具模式（道路）」「工具模式（建筑）」；游戏里只有一份值的项不再举分组例子），实机验证待做；
> 线上（Paradox Mods，ModId 160529）保持 Private，发布与更新由作者本人处理。

## 功能

- 每个存档一份记忆（`ModsData\ToolModeMemory\<存档名>.json`，文件名 = 「载入游戏」里看到的存档名；
  打开自动存档时记忆仍写进它**原存档名**的文件并覆盖它）
- 退出覆盖写入，下次进入自动恢复；**另存为**当场将当前记忆复制给新档名
- 五个标签页：总开关 / 建筑与服务 / 功能 / 道具 / 关于。每页只列属于这一页的工具项
- **两类开关分工明确**（v0.9.0）：
  - **总开关**管全部。出厂关闭，装好后什么都不改变，主动打开才生效
  - **三个分页开关**（记住建筑与服务／功能／道具的设置）管**记忆**：打开就实时记录、读档自动恢复；
    关掉就不记录也不恢复，共用范围自然也无从设置
  - **每一项自己的开关**只管**共用范围**：关掉只是把它的共用范围灰掉，这一行交回原版
- 面板上的**每一行都是独立一项**：笔刷种类 / 笔刷粗细 / 笔刷强度分开，另有目标高度、年龄、保留年代、距离等
- 每一项都写明这一行到底在哪些工具上出现（例如「只有地面平整与斜坡有」「只有树有」）
- 「共用范围」：同组 / 同菜单 / 同类 / 全局共用 / 全局不共用。
  **同组 = 菜单栏里的分组**（工具栏的「菜单 → 分类」）：功能区里的住宅区就是一个分组，
  低密度、中密度、高密度住宅共用一份；切到商业区就是同一菜单下的另一个分组。
  每一条共用范围都先给定义再给例子，例子只举本页、本类工具（v0.9.1）。
  **「同类」只在建筑与服务页提供** —— 原版只记忆道路工具的设置（按资产分类分组），
  功能页与道具页既没有原版依据，彼此的模式枚举又差别极大，按同类归组会把不同枚举混在一起
- 功能页与道具页**不提供推荐**：每一项出厂关闭、按原版行为走。
  建筑与服务页里工具模式推荐「同类」、高度推荐「同组」，其余按原版
- 尊重资产自己的取值限制：共用的数值超出该资产允许的范围时，那件资产不被改写
- 没安装 Anarchy 时，Anarchy 的工具项整块不出现。Anarchy 板块：主开关、左侧和右侧、常规（道路工具），
  以及**物件高度**（摆件工具面板上那一排：锁定变换 / 高度 / 高度变化范围 / 抬高降低的幅度，一起记忆）
- 「记忆管理」：重置记忆、打开记忆文件夹
- 12 种官方语言
- 零 Harmony，不修改游戏文件

## 本地构建

```powershell
dotnet build -c Release
```

部署到游戏 Mods 目录由官方工具链 `DeployWIP` 完成。  
离线回归测试（不需要游戏，也不写真机目录）：

```powershell
dotnet build -c Release                              # T1：0 警告 0 错误
dotnet run -c Release --project tests\StoreHarness   # T3：无游戏依赖的回归壳（538 项）
python tests\version_check.py                        # 版本三处字面量 + 产物里的 UTF-16LE 版本串
python tests\l10n_check.py                           # 12 语言 × 38 项文案齐全
python tests\option_panel_check.py                   # 选项页结构 + 出厂默认值 + 推荐档位
```

各脚本的判定条数一律从源码（`ToolItemCatalog` 的目录）推，不写死常数 ——
加一项就会变红的数字比「永远绿的」常数更可靠。

## 共用范围

五种共用范围在三页上**结构相同、归类口径不同**（v0.7.0，owner 需求 2）：

| 档位 | 含义 | 哪几页提供 |
|---|---|---|
| 同组 | 同一菜单下的同一分类（= 原版道路工具的粒度） | 三页都有 |
| 同菜单 | 整个菜单共用（道路、教育…） | 三页都有 |
| 同类 | **不**按工具栏分类，而按资产服务谁归群（`AssetClass.cs`）。判不出就退回按单个资产记 | **只有建筑与服务页** |
| 全局共用 | 本页内所有支持本项的工具共用一份 | 三页都有 |
| 全局不共用 | 本页内每一项各记一份 | 三页都有 |

「同类」只在建筑与服务页提供（v0.9.0）。理由：原版唯一会落盘的记忆实现是 `NetToolSystem`
的 `LoadToolPreferences` / `SaveToolPreferences`（`NetToolSystem.cs:5626-5663`），它按
`UIObjectData.m_Group`（= 资产分类）分组 —— 那正是「同组」。功能型工具与摆件工具
**原版一个值都不记**，所以对它们而言「原版档」无意义；而这些工具彼此的模式枚举差别极大，
按「同类」归组共用等于把不同枚举的值塞进同一把键，会写下玩家设不出来的组合。

「建筑与服务」的「同类」：小巷 / 各车道数的道路 / 高架 / 隧道同为车行，小型停车场与大型停车场同为一类，
步行道、地铁轨道、火车轨道、电缆各算一类，小学与中学同为教育服务；**桥梁、埠头、交叉路口各自单独成类**（与道路不同类）。

「三页各记各的」是硬规则：**同名的两行也绝不通气**。实现方式不是另起一套桶名，
而是完整记忆键带上域前缀（`A|` / `F|` / `I|`，见 `Memory/MemoryKeys.cs`）——
桶名沿用旧名，0.6.2 之前玩家记下的地形笔刷、对齐开关才不会整桶变成不认识的数据。

只有一个分组的工具（地形改造、树木）在说明里直说「同组和同菜单选出来的是同一批工具」，
不假装还有「另一组」——那是 owner 0.9.1 点出来的问题。

「同组」「同菜单」**读工具栏的实时层级**（`UIObjectData.m_Group` → `UIAssetCategoryData.m_Menu`）：
Asset UI Manager 这类模组重排过分组，本模组就跟着重排后的分组共用，不再提供「按原版分组」的开关
（v0.6.0 起取消）。做不了回退的原因很直接 —— 工具栏数据只有这一份，被改写之后原地不存在
「原版那份」，冻结第一次解析到的位置也换不回原版分组。
「同类」不看工具栏摆它在哪，只读资产自己的组件（`RoadData` / `TrackData` / `PathwayData` /
`WaterwayData` / `NetData.m_*Layers` / `UtilityObjectData` / 车道实体的 `*LaneData` /
`ServiceObjectData` → `ServiceData`），所以它本来就与其它模组的改排无关。桥梁、埠头、交叉路口、停车场四类看的是用途标记
（`BridgeData`、`PlaceableNetData.m_PlacementFlags & ShoreLine`、`AssetStampData` + `SubNet`、
`ParkingFacilityData`），判据与原版资产编辑器的分类查询逐字一致
（`EditorAssetCategorySystem.GenerateRoadCategory` / `GenerateBridgeCategory`），
所以我们在编辑器里看到的那套「道路 / 桥梁 / 交叉路口」划分就是本模组的划分。
唯一的例外是地区主题 / 数据包两行：它们的值是筛选面板自己的状态，
仍按（菜单+分类）记录，否则原版换分类时的清空会被误当成玩家取消勾选。

键一律用资产/分类的稳定名字，不用实体索引，所以加装或移除 DLC、创意工坊后不会串记忆。

## 三页与工具项（v0.9.1）

每一项都归入三个标签页之一，**每一项都是游戏面板上的一行**：

| 页 | 归属 | 项 |
|---|---|---|
| 建筑与服务 | 用工具栏资产干活的工具 | 地区主题、数据包、工具模式（道路）、工具模式（建筑）、高度、并列模式、对齐（道路）、对齐（建筑）、地形、地下模式（10 项，出厂开 4 项）；Anarchy：主开关、左侧和右侧、常规、物件高度（4 项，出厂关） |
| 功能 | 六类非资产工具 | 地区主题、数据包、工具模式（功能区）、对齐（功能区）、对齐（区域工具）、对齐（标记与预制对象）、地下模式、地形、笔刷种类、笔刷粗细、笔刷强度、目标高度、距离、颜色（14 项，**出厂全关**） |
| 道具 | 城市美化八类道具 + 植被（树） | 地区主题、数据包、工具模式、距离、笔刷种类、笔刷粗细、笔刷强度、年龄、保留年代、对齐、地形、地下模式（12 项）；Anarchy：主开关、物件高度（2 项）——**出厂全关** |

行归属的依据是游戏真实的工具×行矩阵（`research/round4/vanilla_rows.md`，逐条带 `文件:行号`）：
「高度」「并列模式」只有道路工具有；「目标高度」只有地形的平整与斜坡两种资产有；
「年龄」「保留年代」只有树有；「距离」只有直线/曲线模式有；「颜色」只有路线工具有
（`IColored` 的唯一实现者是 `RoutePrefab`）。

出厂默认值（v0.9.0，按 owner 要求收紧）：

| 页 | 出厂开着的项 | 说明 |
|---|---|---|
| 建筑与服务 | 工具模式（道路）、工具模式（建筑）、高度、对齐（道路）、对齐（建筑） | 这几项原版都没有「同类」记忆，按同类/同组分开记确实有增益 |
| 建筑与服务 | 其余（含并列模式） | 出厂关。并列模式原版就按同组记，加档没有增益 |
| 功能 / 道具 | **一项都不开** | 原版对这两页的工具一个值都不记，所以「原版档」无意义，出厂保持原版 |

- **功能 = 六类**：4 个功能区（住宅/商业/工业/办公）、3 个区域工具（市辖区创建工具、专门产业区工具、表面区域规划工具）、
  交通运输菜单里的所有路线工具、9 个地形改造工具、5 个空间与区域工具（公园区域、徒步区域、散步区域、清空区域、剪裁地面）、
  以及所有标记与预制对象（动物生成工具等）。判定见 `FuncClass.Kind()`。
- **道具 = 城市美化的八类道具 + 植被（树）**，判据是物件工具的菜单名与分类名（`PropClass.IsPropMenu`）。
  树是用摆件工具刷出来的，与公园道具同一套面板行，所以「年龄」「保留年代」放在这一页。
- **其余全部算资产**。第三方模组（目前只有 Anarchy）只在它的面板行认得出时才纳入，认不出就整块不出现 = 原版行为 + 不记忆。
- 面板上没有的行绝不记录、绝不写回：例如给一件普通贴花写「年龄」不会影响面板，却会悄悄改变它生成物体的方式。

## 资产自带的取值限制（v0.6.0）


「全局共用」和资产自身的限制会打架：地下管线这类资产只能在某个高度以下（水管最高只到地面以下），
而共用的记忆值可能是 0m。规则由 `Memory/ValueLimit.cs` 统一成一处，两侧各一条：

- **写回**（`ToolMemoryBridge.ApplyElevationField`）：共用值超出这件资产的范围就一个字节都不写。
  面板绑的正是 `tool.elevation`（`Game.UI.InGame/ToolUISystem.cs:149`），写进去就是把面板设成
  这件资产做不到的 0m；原版会在每帧的 `InitializeRaycast` 里按新资产的范围夹一次
  （`NetToolSystem.CheckElevationRange` L6023-6030、`InitializeRaycast` L5928-5937），
  我们不写 = 面板直接停在它自己允许的那个值上，不用等一帧去纠正一个假值。
- **捕获**（`ToolMemorySystem.CaptureNow`）：判的是**这个值本身**够不够得着。
  从道路切到水管时工具里留着的是道路的 0m，那不属于水管，记下去要么污染共用桶（把道路一起拽走），
  要么变成这件资产永远用不了的死值，还会挡掉玩家后面真正选的数值。
  玩家在**这件资产上**主动改出来的合法值（水管改到 -30m）一律照常记 —— 共用范围带着整组一起变，
  这正是「共用」的定义，也与原版共用同一个 `m_DesiredElevation` 的行为一致。

限制一律**自动读资产自己的数据**，不写死任何资产名：
高度取 `Game.Prefabs.PlaceableNetData.m_ElevationRange`（`Bounds1`），按 prefab 缓存（`s_LimitCache`，
`ForgetNames()` 时清空）。读不到 / 数据残缺（min>max、NaN、无穷）一律当「不限制」，
绝不让「读不到限制」退化成「什么都不写」。判定带 5cm 宽容度（`ValueLimit.kTolerance`），
只为吃掉浮点与 1cm 存储的往返误差，远小于任何可用的高度档位。

工具模式、对齐、配色这类「可选集合」项不需要这套规则：原版本来就按资产派生可选项，
我们写回时走的正是它自己的判据（`GetUIModes` L5402 / `actualMode` L5120 /
`GetAvailableSnapMask` + `GetActualSnap`，配色看 `m_HasPlacementColor`）。

## 进档与退档的流程纪律（v0.5.0）

原版把 `onGameLoadingComplete` 一次性交给我们，进档要做完四件事：认存档名、读记忆、
把系统启用状态对齐、写回面板。v0.4.0 把这四件事写在同一个 `try` 里，
任何一步抛出异常，后面三步全部没跑 —— 玩家看到的就是「模组开着，进档却什么都不生效；
把开关拨一遍又好了」。现在（`ToolModeMemoryMod.EnterSave`）：

- 每一步各自 `RunStep()`，失败只记本步的日志，后续步骤照跑；
- 认名失败时必须落到**本局专属**的临时名（`StartUnnamedSession`），
  绝不沿用上一个存档的文件名 —— game→game 直接切档不经过主菜单；
- 所有 `catch` 一律经 `Fail()` 输出**堆栈前 5 帧**，不再只留一个异常类名。

捕获闸门（`Memory/SaveSessionGate.cs`，纯逻辑、离线可断言）：

- 不在存档里不捕获、不落盘：主菜单 / 编辑器里 `OnLeavingGame()` 曾经照样跑捕获，
  并在记忆文件夹里留下对不上号的 `_unsaved_xxxx.json`；
- 进档后 1 秒是稳定期：**每帧写回、不捕获**。原版在 `onGamePreload` 里
  `ResetToolPreferences()`，工具成型又比进档回调晚几帧，
  这段时间一捕获就会把原版默认值记成玩家的选择，下一次进档读到的就是这份被污染的记忆；
- 总开关在存档内被重新打开时同样进入稳定期；
- 退出存档前那一次捕获不受稳定期限制（`AllowFinalCapture`），玩家秒进秒退也不丢记录。

## 开发与验收纪律（每次改动都要过一遍）

**性能**：任何新代码都不许进入每帧路径做可避免的工作。

- 键、名字、分类判定一律走缓存，缓存只在「工具 / 资产真的换了」或隔 2 秒时重算
  （`ToolMemorySystem.RefreshKeyCache`），不允许每帧重算字符串键。
- 需要扫磁盘或资产库的事（例如自动存档回溯原存档名）只在进档回调里做一次，绝不放 `OnUpdate`。
- 反射解析外部模类型的时机不能早于对方加载：懒解析 + 重试 + 次数上限
  （`ToolMemoryBridge.Anarchy()`），解析成功后热路径只剩一次字段读。
- 写盘失败必须退避（10→20→…→300 秒），否则 Dirty 不清会导致**每帧**重试文件 IO。
- **每帧路径不许有可避免的堆分配**：游戏跑 Mono/Boehm（`boot.config` 里的 `gc-max-time-slice`
  就是它的增量回收参数），不分代，每帧扔几百字节会在长时间游玩后换成全堆扫描卡顿。
  值类型「按资产派生」的一律按 prefab 记忆（`s_HasColorCache` 等，`ForgetNames()` 清、`kCacheCap` 封顶），
  不要每帧反射取值（`FieldInfo.GetValue` 对值类型必装箱）。已知保留两处并写清理由：
  `m_DesiredElevation`（要的就是跨资产那个意图值，1 盒/帧）与 Anarchy 的四项（外来类型，免装箱只能降频探测，
  风险不对称）。
- 新增项要先在 `tests/StoreHarness` 里补断言，再谈实机。

**卸载安全**（取消订阅 / 删模组文件夹之后，下次进游戏不许报错，也不许留下副作用）：

- 每个挂上去的东西都要有对应的摘掉动作，并在 `IMod.OnDispose` 里执行：
  `GameManager.onGameLoadingComplete/onGameSaveLoad/onGamePreload`、`Application.quitting`、
  `AppDomain.CurrentDomain.ProcessExit`、原版 `ToolSystem.EventToolChanged/EventPrefabChanged`
  （`ToolMemorySystem.Detach()`，不能只依赖 `OnDestroy`：World 不重建就不会调用）、
  12 个本地化词条源（`RemoveLocaleSources()`，本地化管理器活得比我们久）。
- 静态缓存里存的游戏对象在退出前 `ToolMemoryBridge.ForgetNames()` 清掉；
  静态 `ToolModeMemorySettings.Instance` / `Store` 置 null，让任何迟到调用都自然早退。
- 不往存档里写任何东西，不改游戏文件，不用 Harmony —— 卸载后原版行为自然完整。

**工具模式与对齐为什么拆成几行**（v0.9.2）：同一个行名在不同工具上是不同的可选集合 ——
道路工具的模式是直线/简单曲线/复合曲线/连续/网格/替换，建筑工具是放置单个/升级/移动/刷涂…，
所以记忆键本来就按工具类别分开存。设置页只列一行时，「全局共用＝所有显示这一项的工具共用设置」
那句话就不成立（道路设的值建筑读不到），所以按工具类别拆成独立的两行，各管各的。

每一行 = 一个「是否恢复」开关 + 一个「共用范围」下拉；五种范围的定义就写在本行的说明里
（不再单开一个说明板块，模板 + 例子逐项拼装，见 `LocaleTable.ScopeDescription`）。

**开关与记忆的分工**（玩家问得最多的一条，源码依据 `Systems/ToolMemorySystem.cs`）：

- «启用模组» 开着：**每一项都在记录**，与该项「是否恢复」开关无关（`CaptureNow` 只看大开关与所在域的域开关）。
  关掉某一项只是不写回，历史不会丢，再打开时读到的还是原来那份。
- 三个分域开关关掉：**该页连记录一起停**（开关的名字就是「启用…的记忆」，只拦恢复不拦记录
  等于玩家关掉道具页之后值还在往文件里写，与字面承诺相反）。
- «启用模组» 关掉：不记录、不写回、三页所有设置同时失效（灰掉），系统连每帧都不进，
  下一次进存档就是完全原版行为。
- 大开关的自动反映：三块域全关 → 大开关跟着关；任一块打开 → 大开关跟着开。
  这个反映**只在玩家手动改动时生效**（`Ready` 之后）；读盘期间不反映，
  否则「大开关=关 + 资产=开」这种玩家手动组合会被反序列化顺序改写。
- 每一项的「是否恢复」开着：按该项设定的共用范围把面板调整到记忆值（`ApplyNow` 逐项判 `IsItemEnabled`）。
